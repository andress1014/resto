# plan - frontend-lineagrafica - ronda 4 - Hallazgos de verificacion visual

## Contexto (leer con atencion)

El orquestador verifico en Chrome de verdad (stack Docker, admin :3000, PWA :3001): **A1-A5 pasan pero la UI se ve rota**. Leccion clave: **jsdom no aplica el CSS real** — nuestros tests de componentes pasan con la UI visualmente rota. Cada fix de esta ronda debe incluir, cuando aplique, un test que hubiera FALLADO antes del fix (asserts sobre el CSS real servido leido como texto, o sobre el inline style renderizado: prohibido volver a introducir referencias circulares `'--x': 'var(--x)'`, y `[data-component="bento-card"]` debe declarar `padding` y `background-color` en bento.css).

**Verificacion visual**: ni tu ni yo tenemos navegador. Declara en tu `ejecucion` exactamente que NO pudiste verificar visualmente; la verificacion visual la repite el orquestador en Chrome. Lo que si debes hacer: razonar cada fix contra la spec CSS (la causa raiz de H1 era una custom property circular: invalida en computed-value time, por eso el fondo quedaba transparente aunque "se viera bien" en el codigo).
